## T04：用户与密码模型

本步仅增加账号基础模型与服务，不创建登录页面、账号管理页面或管理员初始化流程。新增 V2 迁移创建 `app_user`，包含唯一登录名、密码哈希、姓名、角色、状态、强制改密标志、凭据版本及 UTC 时刻；MySQL CHECK 约束限制登录名格式、三种角色、两种状态和非负凭据版本。`AppUser` 不提供角色修改方法，状态和密码变化会递增 `credential_version`。登录名统一 trim 后用 `Locale.ROOT` 转小写，并限制 ASCII 字母、数字、下划线共 3—50 位。

采用 Spring Security `PasswordEncoder` API 与 BCrypt 强度 10。密码策略为 12—64 个 Unicode 字符、UTF-8 不超过 72 字节；不修剪密码，因此空格仍按密码原样编码。姓名 trim 后为 1—100 个 Unicode 字符。账号服务只保存单向编码值，支持按归一化登录名查找。计划与需求基线已同步此密码政策；Spring Security 采用单向密码编码的设计参见 [密码存储文档](https://docs.spring.io/spring-security/reference/features/authentication/password-storage.html)。

## T05：登录退出与管理员初始化

新增 Spring Security 表单认证、登录页与退出按钮；登录名继续执行 trim/小写归一化。未知账号、错误密码和禁用账号都进入同一失败地址并显示相同提示。新建/重置密码标记的账号登录后由过滤器限制到密码页、静态样式和退出；改密时先核对当前密码，再执行 T04 的 12—64 Unicode 字符与 BCrypt 72 UTF-8 字节规则。保存后将 `must_change_password` 清除、`credential_version` 加一、使当前 HttpSession 失效并要求重新登录。CSRF 仍由 Spring Security 默认机制保护，包括登录、登出和改密表单。

## T06：统一权限与会话有效性

为 `/admin`、`/staff`、`/reader` 增加基础工作区，并在 Spring Security 服务端按角色限制入口：ADMIN 可进入管理及工作人员区域，LIBRARIAN 只能进入工作人员区域，READER 只能进入读者区域。链接是否显示不作为权限依据；直接访问和伪造查询参数也由后端拒绝。`CurrentIdentityService` 从安全上下文提供已验证的账号 ID、登录名、角色，并提供读者账号 ID 和“只能访问本人账号 ID”的统一检查；未来读者档案以 `app_user_id` 关联到此身份，不信任请求中的角色或 owner ID。

新增 `SessionValidityFilter`，在每个非公开、非登出请求授权前从当前数据库重新读取账号，核对账号仍为 ACTIVE 且数据库 `credential_version` 与会话中的版本一致。用户被禁用、密码重置或凭据版本变化后，旧 HttpSession 会立即失效并跳转到登录页；读写请求采用同一复核。登录页展示统一的“登录状态已变化”提示。登录、退出、静态资源和错误页不需要读取账号状态；首页对已登录用户也会检查会话有效性，因为它会显示账号信息。

## T09：书目资料管理

新增 V5 迁移创建 `book` 表，外键引用分类并使用 `ON DELETE RESTRICT`；因此分类被书目引用后，MySQL 会拒绝删除。书目保存书名、作者、可选出版社/出版日期/ISBN/简介、分类、ACTIVE/ARCHIVED 状态和乐观锁版本。书目没有物理删除入口。`BookService` 集中处理输入验证、分类有效性、ISBN 唯一性、版本冲突和归档；`BookController` 及 `/staff/books` 页面供管理员/馆员使用。修改表单提交隐藏版本号，服务先核对版本，JPA `@Version` 再拦截两次读取间发生的并发提交。归档后不可编辑，面向读者的可见书目查询方法只返回 ACTIVE。

ISBN 归一化去掉空格与连字符并转成大写，校验 ISBN-10/13 格式和校验位；ISBN-13 要以 978 或 979 开头。未填写或只含空格的 ISBN 存为 `NULL`，MySQL 唯一索引允许多条 NULL。分类被书目引用时由数据库外键兜底，页面不提供物理删除书目。

归档仅能从 `BookService.archive` 进入，并调用 `BookArchiveGuard` 保护点。本步完成时尚无副本、借阅和预约数据表；T10 已增加副本状态检查，T11 已验证归档书目不出现在检索目录中。T13/预约范围到来时仍须为未还借阅和活动预约增加归档阻止检查，并用 MySQL 联测“有关联时不能归档、关联结束后可以归档”。

## T10：实体副本管理

新增 V6 迁移建立 `book_copy` 表：每册副本独立保存书目、唯一馆藏条码、可选馆藏位置、状态、版本及创建/更新时间；MySQL 外键阻止删除仍有副本的书目，状态 CHECK 只接受 `AVAILABLE`、`ON_LOAN`、`WITHDRAWN`。T10 不提供借出入口，`ON_LOAN` 仅作为借阅任务将使用的受约束状态。

`BookCopyService` 按工作人员角色校验登记、查询和注销。登记与归档都会先锁同一本书目行：这样正在登记副本时不能同时归档，也不能在归档提交后再登记副本。新副本只能由服务创建为 `AVAILABLE`；只有 `AVAILABLE` 能转为 `WITHDRAWN`，没有任意改状态或物理删除入口。归档保护点现在检查所有副本都为 `WITHDRAWN`；无副本或全已注销时可以归档，仍有可借或借出状态副本时会拒绝。

## T19：表单、导航与页面体验

新增共享 `FormFeedback` 和 Thymeleaf 字段提示片段。表单服务端校验失败时，控制器给出中文总提示和对应字段提示，通过一次性跳转状态保留书名、姓名、分类名等明确列出的非敏感值；提交密码不会进入保留值。密码字段始终不带回填值。字段错误通过 `aria-invalid`、`aria-describedby` 和提示文本关联；成功/失败通知分别标为状态消息和提醒。

书目、分类、副本、账号、本人资料、改密和借还表单已接入上述反馈。补充缺省参数及出版日期的中文校验，重复分类会定位到分类名称；简介超过限制后只保留最多 2,000 个字符供修正。Thymeleaf 继续使用默认 HTML 转义。分页导航改为当前页附近的有限页码窗口，借阅和审计查询将超出末页的页码收敛到末页；非法书目编号显示专用 404 内容。新增 403、404、500 和通用错误页面；应用错误响应关闭异常、消息、绑定细节及堆栈输出。CSS 增加表单错误/状态、焦点和窄屏最小宽度约束；首页说明同步到当前已开放的借阅与角色工作区功能。
