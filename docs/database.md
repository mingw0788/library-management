# 数据库结构与并发约定

本文件记录跨任务共用的 MySQL 结构约定、事务隔离和行锁顺序。新增借还、续借或预约入口时必须遵守本协议，并用真实 MySQL 测试验证；数据库约束是服务校验之外的最后防线。

## 数据与时间

- 迁移由 Flyway 按版本顺序执行；当前迁移至 V12（预约保留到期），数据库结构与实体由 Hibernate `validate` 核对。应用运行账号只访问 profile 指定的专用数据库。
- 事务使用 `READ COMMITTED`，表使用 InnoDB、字符集 `utf8mb4`。
- 事件时间使用 UTC 的 `Instant`，在 MySQL `DATETIME(6)` 中按 UTC 保存；业务日历使用 `Asia/Shanghai`。应还日使用 `LocalDate` / `DATE`，从借出时刻对应的上海本地日期加配置的自然日数计算。应还当天结束前不算逾期；仅当上海本地当前日期晚于应还日才逾期。规则计算注入 `Clock`，不得依赖运行机器默认时区。
- 循环规则集中于 `CirculationPolicy` 和 `LoanRules`：同时未还上限及借期可配置，当前默认分别为 5 册和 14 天。X01 允许每条借阅最多续借一次，应还日从原 `due_date` 顺延 14 天。X02—X04 的预约队列、72 小时保留、取书及到期释放在 test/prod profile 启用；默认与 dev profile 关闭。

## 借阅约束

V7 的 `loan` 表分别外键引用读者档案、实体副本、借出办理账号和（归还后）归还办理账号，均禁止删除历史所引用的行。`returned_at` 和 `return_operator_id` 必须同时为空或同时有值；归还时刻不得早于借出时刻。

MySQL 生成列 `active_copy_id` 在未归还时等于 `copy_id`，归还后为 `NULL`，并对该列建立唯一索引。因此同一副本只能有一条未归还记录，但可以保留任意多条已归还历史。不要用 `UNIQUE(copy_id, returned_at)` 代替：MySQL 唯一索引对 NULL 的处理不能表达“仅一条未归还记录”的规则。

该唯一索引不负责读者额度、逾期或同一书目限制。`LoanCheckoutService` 在同一事务中重新读取并校验账号、档案、书目、副本和借阅数据，再创建借阅记录并将副本改为 `ON_LOAN`。任一步骤失败都会整体回滚。

## 行锁顺序

所有会改变读者资格、书目状态、副本状态或借阅状态的事务遵循下列顺序，涉及某一类数据时跳过无关层级，但不得反向加锁：

1. `app_user`：借阅读者账号及办理员工账号；
2. `reader_profile`：借阅读者档案；
3. `book`：副本所属书目；
4. `book_copy`：具体副本；
5. `loan`：借阅记录。
6. `reservation`：预约记录，最后加锁；分配或取书事务不得先锁预约再请求用户、书目、副本或借阅行。到期任务跳过用户/档案层，先锁 `book → book_copy`，再按预约编号升序锁过期预约和需要的 FIFO 前缀。

借出、归还或续借时，先用普通只读查询解析输入标识，不持有锁；随后在一个 `READ COMMITTED` 事务中按上述次序锁定行，再重新读取并校验所有会影响决定的状态，最后写入。借出要串行保护同一读者的额度、逾期及同书目规则，也要串行保护副本与书目；归还和续借先确定借阅对应的读者、书目和副本 ID，再依次锁定并在最后锁借阅记录，随后复核记录状态。续借会锁住读者账号以与禁用和其他借阅事务串行，并在锁内重新检查账号启用、本人归属、当前借阅、日期、续借次数和本人其他逾期记录。不得只根据事务开始前的页面状态作决定。

预约创建先只读检查请求参数，然后在一个事务中依次锁 `app_user`、`reader_profile`、`book`，再按副本 ID 升序锁定该书目所有未注销副本，最后检查并插入 `reservation`。账号和档案锁使该读者的借阅资格与新借/归还串行；书目锁使书目状态和馆藏变更与登记、借出、归还串行；副本锁保证“至少一册未注销且没有可借副本”的两项检查基于同一组稳定行。取消先只读解析预约关联，再按 `app_user → reader_profile → book → book_copy（READY 时）→ reservation` 顺序加锁；禁用先锁账号和档案，再按书目 ID 升序逐本处理，释放其 HELD 副本并在同一事务重分配。涉及取书或归还的分配会在 `loan` 之后锁预约。任何预约写入都不得先锁 `reservation` 再请求更高层级的行锁。

活动预约定义为 `PENDING` 或 `READY`。V11 用生成列把活动记录的读者编号暴露给唯一索引 `(book_id, active_reader_id)`，并为 READY 记录生成 `active_copy_id` 唯一索引，保证同一读者同一书目最多一条活动预约、同一副本最多保留给一人。终态 `CANCELLED` / `FULFILLED` / `EXPIRED` 保留历史；V12 为 EXPIRED 增加 `expired_at`，且只允许截止时刻或之后过期、只允许截止前取书。FIFO 顺序为 `created_at ASC, id ASC`；本人页面只返回当前登录读者的数据和其排队位置，不暴露其他读者资料。工作人员可查看 READY 队列和核对读者证号，取书时借阅、预约和副本状态在同一事务更新。

`book_copy` 新增 `HELD` 状态。归还或登记副本在持有书目锁时触发分配；分配只读取队列候选账号启用状态，不锁其他读者账号或档案，再依 `book → book_copy → loan（归还场景）→ reservation` 写入。每册分配后记录 `hold_expires_at = 分配时刻 + 72 小时`。取书在锁住目标读者账号、档案、书目和副本后重新核对额度、逾期和同书目借阅；资格暂不满足时事务不改动预约或 HELD 副本，预约保持 READY 到截止。到期扫描每分钟运行；取书请求在提交前再次核对 `now < hold_expires_at`，到期时同步释放并分配给队列下一位，不依赖定时器及时执行。

账号禁用首先锁 `app_user`。如果禁用先提交，后续借出重新读取后会拒绝；如果借出先完成，之后禁用保留既有借阅，归还仍允许。禁用不得删除读者档案或借阅历史。

书目归档首先锁 `book`，并在锁内检查副本状态、未还借阅和活动预约。副本注销按 `book → book_copy` 锁定，仅允许 `AVAILABLE`；如果活动预约存在，禁止注销最后一册未注销副本。借出按 `book` 再 `book_copy` 锁定并重新确认书目仍有效、副本仍可借，因而与归档、注销遵守同一顺序。

一笔事务需要锁多行同类型记录时，按主键升序锁定。锁持有期间不等待用户输入、不执行外部网络调用；死锁仍需由数据库检测并回滚，用户可安全重试失败请求。

## 实施与验证边界

`LoanEligibilityPolicy` 提供统一业务资格判断：读者账号有效、书目有效、副本可借、没有逾期未还、未达到配置上限、没有同书目未还记录。该组件为只读策略，不自行获取上文全部锁；借出入口须先遵守锁顺序，再在同一事务中调用资格判断并完成状态写入。`LoanCheckoutService` 先用只含主键的投影解析证号和条码，避免把未加锁的实体留在持久化上下文；加锁后重新读取并校验状态。

T12 已在 MySQL 8.0.44 测试库验证生成列唯一约束拒绝重复活动借阅、归还后允许再次借出，以及外键、归还字段配对和资格/日期边界。X01 的 V9 将续借次数检查约束改为 0—1；续借仍按相同锁序在 `book_copy` 后锁 `loan`，同事务更新应还日期、次数和审计。实际资格、并发与回滚结果见 [X01 记录](progress.md#x01)。T13 已用独立事务测试同副本竞争、同一读者争抢最后额度、写入失败回滚，并验证借出中的副本不能注销、相关书目不能归档。T14 的归还入口按相同锁序在 `book_copy` 后锁 `loan`；真实数据库测试覆盖并发归还、重复请求、禁用读者归还、归还后再借及事务回滚。

X02 的 V10 建立预约队列；X03 的 V11 增加 READY 分配与取书；X04 的 V12 增加到期终态、分钟级扫描和实时过期处理。归还或新增副本按 FIFO 分配；读者取消、账号禁用或超时会释放保留并在事务内继续分配。活动预约会阻止续借、归档和最后可流通副本注销。test/prod profile 开启服务、页面和调度；默认与 dev profile 关闭。prod profile 的配置已启用，但未实际部署。验收证据见 [X03](progress.md#x03) 与 [X04 记录](progress.md#x04)。

T15 的查询是只读操作，不改变借阅或副本状态，也不写入每日逾期标志。读者范围由已认证用户关联的 `reader_profile` 确定；工作人员可按读者证号/姓名、条码、借出日期和当前/已还状态筛选全馆记录。日期边界按 `Asia/Shanghai` 转为 UTC 瞬间后查询；未还逾期和已归还晚还由 `LoanViewMapper` 在显示时分别派生，晚还历史不计作当前逾期。
