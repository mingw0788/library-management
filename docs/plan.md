## 1. 项目目标与范围

### 1.1 要解决的问题

通过浏览器管理图书资料、实体馆藏、读者以及借还记录，替代人工表格登记。系统须能回答：馆里有哪些书、某本书有几册可借、谁借走了哪一册、何时应还、哪些借阅已逾期。

学习目标是理解 Java Web 的请求处理、页面渲染、数据库持久化、登录授权、事务、测试和 Git 协作。每步实施都应解释涉及文件、数据流和关键设计；不要求预先掌握全部框架。

### 1.2 默认假设

| 项目 | 本计划的默认决定 |
|---|---|
| 使用场景 | 单馆、小规模教学或个人项目；先本地运行，再制作可部署交付物 |
| 页面形式 | 中文网页；Spring MVC + Thymeleaf 服务端渲染；同一应用提供页面和业务处理 |

| 角色 | 管理员 ADMIN、图书管理员 LIBRARIAN、读者 READER；一个账号一个角色 |
| 借阅对象 | 实体副本，不是抽象书目；同一书目可以有多册 |

不实现在线支付、真实罚款结算、采购财务、多分馆调拨、电子书、短信邮件、第三方登录、微服务、Redis、消息队列或独立前端工程。批量导入、文件上传、封面上传另开需求；基础版本只展示文本资料。不要因“以后可能需要”自动加入这些模块。

### 1.4 成功标准

## 3. 角色与权限

“本人”指服务端根据登录身份确定的对象，不能相信请求传来的 readerId。工作人员账号默认没有读者身份；如需要借书，另建 READER 账号。

| 操作 | ADMIN | LIBRARIAN | READER |
|---|---|---|---|
| 登录、退出、修改本人密码和资料 | 允许 | 允许 | 允许 |
| 查询有效书目、查看馆藏状态 | 允许 | 允许 | 允许 |
| 创建/禁用管理员和馆员、重置其密码 | 允许 | 禁止 | 禁止 |
| 创建/维护/禁用读者、重置读者密码 | 允许 | 允许 | 禁止 |
| 修改角色 | 基础版本不提供角色变更；新增正确角色账号代替 | 禁止 | 禁止 |
| 管理分类、书目、副本 | 允许 | 允许 | 禁止 |
| 办理借出、归还 | 允许 | 允许 | 禁止 |
| 查看全馆借阅和逾期记录 | 允许 | 允许 | 禁止 |
| 查看本人借阅记录 | 使用独立读者账号 | 使用独立读者账号 | 允许 |
| 查看完整审计查询页 | 允许 | 禁止 | 禁止 |
| 查看全馆统计 | 允许 | 允许 | 禁止 |
| 续借/预约/取消预约（扩展） | 使用独立读者账号 | 使用独立读者账号 | 仅本人 |
| 按规则配置借期/额度 | 修改受版本控制的配置并重启；本轮不提供设置页面 | 禁止 | 禁止 |

权限必须检查页面请求和写操作，不能只隐藏菜单。LIBRARIAN 即使伪造 role=ADMIN，也不能创建工作人员。禁用账号后，旧会话下一次访问受保护资源应被拒绝；重置密码和本人改密也须使旧会话失效。实现时在相应事务内递增credential_version，每次受保护请求重新比较数据库版本和启用状态，不能只在登录时检查；普通查询和写请求都须覆盖。至少保留一名有效管理员，且并发禁用两名管理员也不能绕过此规则。

## 4. 业务规则基线

| 编号 | 规则 |
|---|---|
| B01 | 每位读者最多同时有 5 条未归还借阅；是否逾期不影响其计入额度。额度、借期作为统一后端配置，启动时校验为正数。 |
| B02 | 应还日期＝借出时刻在 Asia/Shanghai 对应的本地日期＋14 天；应还当天归还不算逾期，次日起逾期。日期边界用可注入时钟验证。 |
| B03 | 新借前必须确认：读者启用、无未归还逾期、未超额度、未持有同一书目的其他未还副本、书目未归档、副本 AVAILABLE。 |
| B04 | 借出记录和副本 ON_LOAN 状态在同一事务中保存；工作人员不能手工修改“可借册数”。 |
| B05 | 归还必须对应仍未归还的借阅；记录归还时刻、归还办理人后把副本恢复 AVAILABLE。重复归还返回“已归还”，不再更新数据。 |
| B06 | 禁用读者禁止登录、新借、续借和预约；工作人员仍可为其办理归还。禁用不删除历史。 |
| B07 | 已被使用的账号、书目、副本、借阅记录不做物理删除；通过禁用、归档或注销处理。分类仅在没有书目引用时可删除。 |
| B08 | 书目只有所有副本均已注销、无未还借阅时才可归档；扩展后还须无活动预约。归档资料仍保留供工作人员查历史。 |
| B09 | 新建副本为 AVAILABLE；仅 AVAILABLE 可转 WITHDRAWN；ON_LOAN 不可注销。基础版不处理丢失赔偿或坏书维修。 |
| B10 | 基础版角色创建后不可改；读者证号和馆藏条码作为稳定标识，不随意修改。工作人员可修正姓名、联系方式和馆藏位置。 |
| B11 | ISBN 可为空；填入时去除空格/连字符并校验 ISBN-10 或 ISBN-13 格式和校验位，归一化值唯一；不同版本使用不同书目。 |
| B12 | 登录名 trim 后转小写，只允许约定的 ASCII 字母、数字、下划线；3—50 位；姓名1—100字、书名1—200字、简介不超过2000字；查询关键词不超过100字，页大小默认20、最大100。 |
| B13 | 初始/重置密码经受控方式交付，不能硬编码到仓库。密码为12—64个Unicode字符；本项目使用BCrypt，并额外限制UTF-8编码不超过72字节，避免静默截断；前后端沿用此规则。首次登录只允许改密和退出。 |
| B14 可选 | 续借最多1次；读者启用、该借阅未还且未逾期、本人无其他逾期，才可将原应还日期＋14天；预约启用后，有该书目活动预约时拒绝续借。 |
| B15 可选 | 预约针对书目：书目有效、至少有一册未注销副本、且没有可直接借出的副本才接受；读者启用且无逾期、额度未满、未持有该书目；同一读者同一书目最多1个活动预约。注销最后一个可流通副本时须无活动预约。 |
| B16 可选 | 队列按 created_at、id 升序；有新可用副本时优先分给最早的启用读者预约，保留72小时。分配不占借阅额度；取书时重新核验全部借阅资格。 |
| B17 可选 | READY 预约仅对应读者可取书；取消、禁用、或 now ≥ hold_expires_at 时释放保留并继续分配。到期判断必须在请求中再次执行，不能只等定时任务。 |

本项目在 T04 采用 Spring Security 的 BCryptPasswordEncoder（强度 10）。密码长度按 Unicode 字符计为 12—64 个，同时 UTF-8 编码最多 72 字节；例如24个常用汉字可通过、25个会被拒绝。密码处理采用框架的单向编码机制，参见 [Spring Security 密码存储文档](https://docs.spring.io/spring-security/reference/features/authentication/password-storage.html)。

## 5. 业务流程与状态

### 5.1 建读者与登录

工作人员填写读者资料 → 后端验证权限和唯一性 → 同一事务创建账号与读者档案 → 提供初始凭据 → 读者登录 → 强制修改密码 → 进入本人首页。创建档案失败时，不留下孤立账号。

### 5.2 书目与入库

建分类 → 建书目资料 → 每一册登记唯一条码 → 初始状态 AVAILABLE → 按副本查询汇总数量。相同书目登记两册，只增加两条副本记录，不重复建书目。

### 5.3 借出

1. 馆员输入读者证号和馆藏条码，系统显示读者、书目、副本和应还日期供核对。
2. 提交后由服务端重新核验身份、角色和 B01—B04，不相信浏览器先前显示的可借状态。
3. 在同一事务内按统一顺序锁定读者和馆藏相关记录，再检查资格、创建借阅、更新副本。
4. 成功后采用提交后重定向，刷新页面不会重复提交；重复/竞争请求得到明确结果。
5. 任何失败都回滚。本步不创建“借阅申请待审核”状态，避免与真实借出混淆。

### 5.4 归还与逾期

按条码找到未归还借阅 → 馆员核对 → 事务中确认仍有效 → 写 returned_at 和办理人 → 恢复副本可借 → 返回结果。禁用读者也可归还。未还逾期＝returned_at 为空且今天晚于 due_date；历史逾期＝归还日期晚于当时 due_date，两种查询不能混用。

### 5.5 可选预约流程

无可直接借副本 → 读者预约 PENDING → 副本归还/新入库 → 按队列分配为 READY，副本 HELD → 本人到馆，馆员核验资格 → 取书形成借阅、预约 FULFILLED、副本 ON_LOAN。取消/超时/禁用则结束预约并重新分配；分配到已满额度或有逾期的读者时保留至截止，由取书规则拒绝不合资格领取，页面需明确原因。

基础版本的状态约定：

| 对象 | 状态/转换 | 禁止事项 |
|---|---|---|
| 账号 | ACTIVE ↔ DISABLED | 禁止删除历史和禁用最后一名有效管理员 |
| 书目 | ACTIVE → ARCHIVED | 有有效副本、未还借阅或活动预约时不能归档；本轮不提供恢复入口 |
| 副本 | AVAILABLE → ON_LOAN → AVAILABLE；AVAILABLE → WITHDRAWN | ON_LOAN 不能直接 WITHDRAWN；WITHDRAWN 不再借出 |
| 借阅 | returned_at 为空＝借阅中；非空＝已归还 | 逾期是派生条件，不存一个每日手工更新的 OVERDUE 状态 |
| 预约（扩展） | PENDING → READY → FULFILLED；PENDING/READY → CANCELLED；READY → EXPIRED | 终态不恢复；不能一条预约保留两册，不能一册保留给两人 |
| 副本（扩展） | AVAILABLE → HELD → ON_LOAN；HELD → AVAILABLE 或重新分配为 HELD | 不允许普通借出绕过 HELD 的归属限制 |

### 6.2 请求链路与职责


### 6.3 环境与配置约定

- 独立项目目录默认 library-management；若当前目录属于已有大仓库，先确认项目根和提交边界，不能在父目录随意初始化或暂存。
- 默认端口8080；冲突时在环境文档记录替代端口。profile 分为 dev、test、prod，测试不得使用开发库或现有业务库。
- 开发库 library_dev，专用测试库 library_test，恢复演练库另取独立名称。凭据通过环境变量/外部配置，仓库只保存无真实值的示例。
- 时刻用 Java Instant；数据库时间字段以 UTC 约定写入和读取，应用/JDBC/数据库会话时区要一致。应还日期用 LocalDate/DATE，不把日期当 UTC 午夜时刻。
- 项目事务隔离基线采用READ COMMITTED并在T03验证；资格和状态在写锁内复核，不靠无锁查询的旧结果决定借出。若更换隔离级别，须先重新评审锁协议和并发用例。
- 开发与测试可用本地 MySQL；使用 Testcontainers 时须先验证容器运行环境，不能因 Docker 不可用把 MySQL 并发验收改成 H2。
- prod 默认禁用演示数据和调试信息，设置安全 Cookie、HTTPS 目标、日志级别和数据库最小权限。启动缺少必填配置时明确失败，不能悄悄连接另一个库。
- Spring Security 对不安全 HTTP 方法提供 CSRF 保护，表单须正确携带令牌；不能为解决403关闭全局保护。参见 [官方 CSRF 文档](https://docs.spring.io/spring-security/reference/servlet/exploits/csrf.html)。

## 7. 数据库设计草案

### 7.1 关系与建模原则

```text
app_user 1 ── 0..1 reader_profile
category 1 ── N book 1 ── N book_copy 1 ── N loan
reader_profile 1 ── N loan
app_user 1 ── N loan（借出/归还办理人）
app_user 1 ── N audit_log
reader_profile 1 ── N reservation N ── 1 book（可选）
reservation 0..1 ── 1 book_copy（仅 READY 时保留，可选）
system_guard：保存管理员变更等必须串行检查的命名锁行
```

库存事实以 book_copy 为准，book 不设置可手工修改的 total_count/available_count。借阅始终引用副本。所有外键默认限制破坏性删除，不使用级联删除借阅历史。

### 7.2 基础字段草案

以下是字段说明，不是建表 SQL；准确长度、索引名称、默认值和迁移文件在对应任务落地。

| 表 | 主要字段与类型草案 | 约束与说明 | 引入任务 |
|---|---|---|---|
| system_guard | guard_key VARCHAR(50) 主键 | 初始化一条 ACTIVE_ADMIN_SET 锁记录；管理员启用/禁用和新增按同一锁串行核验 | T03 |
| app_user | id BIGINT主键；login_name VARCHAR(50)；password_hash VARCHAR(255)；display_name VARCHAR(100)；role VARCHAR(20)；status VARCHAR(20)；must_change_password BOOLEAN；credential_version BIGINT；created_at/updated_at DATETIME(6) | 归一化login_name唯一；role仅三种；status仅ACTIVE/DISABLED；凭据版本变更使旧会话失效；角色不开放修改 | T04 |
| reader_profile | id BIGINT主键；user_id BIGINT；reader_no VARCHAR(50)；contact VARCHAR(100)可空；created_at/updated_at | user_id唯一且外键；reader_no唯一；应用保证其账号role为READER；不重复保存姓名 | T07 |
| category | id；name VARCHAR(100)；created_at/updated_at | trim后名称唯一，明确大小写/排序规则；有书目引用不能删除 | T08 |
| book | id；category_id；title VARCHAR(200)；author VARCHAR(200)；publisher VARCHAR(200)可空；published_date DATE可空；isbn VARCHAR(13)可空；description TEXT可空；status；created_at/updated_at；version | isbn归一化唯一，缺失用NULL；分类外键；ACTIVE/ARCHIVED；version用于避免编辑覆盖 | T09 |
| book_copy | id；book_id；barcode VARCHAR(50)；shelf_location VARCHAR(100)可空；status VARCHAR(20)；created_at/updated_at；version | barcode唯一；book外键；AVAILABLE/ON_LOAN/WITHDRAWN；不开放任意状态编辑 | T10 |
| loan | id；reader_id；copy_id；borrowed_at DATETIME(6)；due_date DATE；returned_at DATETIME(6)可空；checkout_operator_id；return_operator_id可空；renew_count INT默认0；version | 读者/副本/办理人外键；借出时间和应还日必填；归还时刻与归还办理人同时有值；renew_count基础版为0 | T12 |
| audit_log | id；actor_user_id可空；actor_login_snapshot；action VARCHAR(50)；target_type；target_id可空；result；summary VARCHAR(500)；occurred_at DATETIME(6) | 系统任务actor可空；成功业务审计与业务写入同事务；不记密码、完整联系信息、Cookie或令牌 | T16 |

全部业务表使用稳定主键；具有并发编辑风险的实体用 version 做乐观编辑冲突反馈。借阅写操作仍需要事务锁与约束，不能认为 version 自动解决读者总额度。

### 7.3 索引、约束与并发草案

1. 必须唯一：login_name、reader_no、category.name、book.isbn（允许NULL）、book_copy.barcode。
2. 同一副本最多一条未归还借阅。MySQL 草案：在 loan 增加只在 returned_at 为空时等于 copy_id、否则为NULL的生成列，并为其建唯一索引。**不能**仅把 UNIQUE(copy_id, returned_at) 当成有效借阅唯一约束，因为多个NULL不能达到目的。实现时在目标MySQL验证生成列、迁移和JPA映射；无法满足时先设计等价方案，不删掉保障。
3. 建议查询索引：book(category_id,status)、book_copy(book_id,status)、loan(reader_id,returned_at,due_date)、loan(returned_at,due_date)、audit_log(occurred_at,id)。关键词包含匹配不承诺普通B树加速；先满足小规模验收，再按执行计划优化。
4. 借出、归还统一事务；建议按“读者账号/档案 → 书目 → 副本 → 借阅”的顺序加写锁，先定位主键，再加锁并重新核验。所有写入口遵守同一顺序；不在事务里等待人工确认。读者锁保证总额度与同书目持有规则，副本锁与唯一约束保证一册一次借出。
5. 读者禁用、馆藏注销、书目归档需与借还使用兼容锁策略；管理员人数变更通过system_guard行串行核验。细节在T12记录；不得只靠进程内 synchronized 代替数据库一致性。
6. 并发测试用独立数据库连接/事务和受控同步点触发竞争；不能把两个连续调用称为并发，也不能全部包在一个测试事务里。
7. 异常时让事务完整回滚，不在失效事务里吞掉数据库约束异常继续写。锁等待超时给出可重试提示；不对借阅盲目自动重试而创建重复记录。

Spring Data JPA 可以声明查询的锁模式，具体使用方式须匹配选定版本；参见 [官方锁文档](https://docs.spring.io/spring-data/jpa/reference/jpa/locking.html)。本节锁顺序和业务约束是项目设计建议，须通过T13/T14/T21真实数据库测试验证。

### 7.4 预约扩展数据草案

reservation：id、reader_id、book_id、status、created_at、held_copy_id可空、hold_expires_at可空、finished_at可空、fulfilled_loan_id可空、version。

- 活动状态为PENDING/READY；生成活动键并建立唯一约束，保证同一reader_id+book_id仅一个活动预约。
- READY必须有held_copy_id和hold_expires_at；同一副本最多一个READY预约。终态清除保留引用，历史通过fulfilled_loan_id或审计追溯。
- book_copy新增HELD状态；队列索引建议(book_id,status,created_at,id)，到期扫描索引(status,hold_expires_at)。
- 归还、新增副本、取消预约、禁用读者、超时处理都要调用同一分配逻辑；不让不同入口各写一套队列算法。
- X02先确定与核心锁顺序兼容的协议；处理同一书目时必须串行分配。分配不再锁队首读者，不使用会隐式锁用户表的联表写锁；在READ COMMITTED下读取最新已提交的启用状态。禁用先锁用户，再按书目ID顺序锁定并取消其全部活动预约，同一事务完成禁用、版本递增和副本重新分配。所有取书入口仍先锁借阅读者，以保护额度和同书目持有规则。无法证明正确则先解决设计，不开放功能。
- 到期任务每分钟扫描一次；允许最多约1分钟的页面状态滞后，但借出/取消/预约请求必须实时校验截止时刻。任务重复执行仍只能结束一次，不能双重释放。

## 11. 测试、验收和 Git 公共门禁

### 11.1 每步执行顺序

1. 读取项目计划、需求、环境、进度和本地项目说明，检查本步依赖的完成证据。
2. 记录当前Git分支、提交、暂存区和未提交修改。既有修改视为用户工作；不覆盖、还原、擅自暂存或带入提交。如果与本步同文件修改无法安全隔离，先报告具体冲突，停止相关修改。
3. 简述本步目标、涉及模块和验收方法。只完成一个目标，必要关联文件可以一起修改；不顺手重构、不提前实现下步。
4. 实现并解释关键设计。结构变更新增迁移，业务规则变更同步需求和验收。
5. 运行本步测试、受影响回归和构建；涉及MySQL约束/事务/锁时必须使用真实MySQL专用测试环境。T01/T23等文档任务使用文档与可复现性检查，不为凑数编写无意义测试。
6. 测试失败先修复，必要环境不可用视为未验收；不得删除断言、关闭CSRF、跳过集成测试或使用跳过测试选项伪装通过。未通过就不提交、不标记完成、不继续下步。
7. 检查最终差异，确认测试验证的是最终内容。修改了受影响的源码/迁移后必须重跑相关检查；只补写准确的测试结果说明可做文档检查。
8. 在docs/progress.md记录任务号、验收场景、实际命令、结果和拟定提交主题。只暂存本步明确文件/区块，检查暂存差异，再创建本地提交。不使用无差别全量暂存带入已有工作。
9. 提交后核对该提交的文件和剩余Git状态；在对话报告提交标识、通过的检查、遗留问题和下一步编号，随后停止。

当前提交标识在提交后才产生，因此不要求把它预写进同一提交里的progress.md；可在下一任务补录上一步标识，或用任务号/提交主题在Git历史定位。不要为了填当前标识反复修改提交。

提交主题建议：`docs(T01): ...`、`feat(T13): ...`、`fix(T20): ...`。没有实际变更不创建空提交。未配置Git身份或提交钩子失败时，保留修改并报告；不擅自更改全局身份、禁用钩子、强制改历史、push、合并或发布。

## 13. 依赖风险与处理方案

| 风险 | 触发条件/影响 | 预防、验证与处理 | 负责步骤 |
|---|---|---|---|
| R01 版本不兼容 | 旧教程混用新Boot、错误starter或包名，无法构建 | T01核验精确版本和官方文档；依赖由Boot统一管理；升级另开任务，不能猜版本 | T01—T04 |

| R03 需求范围膨胀 | 一次加入预约、罚款、独立前端等，主线无法验收 | MVP先借还闭环；可选功能保持默认关闭，单独选择和逐步验收；新需求先更新基线 | 全过程 |
| R04 书目与副本混淆 | 直接给书目减库存，无法追踪具体一册 | 一册一条码；借阅引用副本；数量查询派生；验收一书两册只借一册 | T09—T14 |
