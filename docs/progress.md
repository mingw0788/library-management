## T04：用户与密码模型

本步仅增加账号基础模型与服务，不创建登录页面、账号管理页面或管理员初始化流程。新增 V2 迁移创建 `app_user`，包含唯一登录名、密码哈希、姓名、角色、状态、强制改密标志、凭据版本及 UTC 时刻；MySQL CHECK 约束限制登录名格式、三种角色、两种状态和非负凭据版本。`AppUser` 不提供角色修改方法，状态和密码变化会递增 `credential_version`。登录名统一 trim 后用 `Locale.ROOT` 转小写，并限制 ASCII 字母、数字、下划线共 3—50 位。

采用 Spring Security `PasswordEncoder` API 与 BCrypt 强度 10。密码策略为 12—64 个 Unicode 字符、UTF-8 不超过 72 字节；不修剪密码，因此空格仍按密码原样编码。姓名 trim 后为 1—100 个 Unicode 字符。账号服务只保存单向编码值，支持按归一化登录名查找。计划与需求基线已同步此密码政策；Spring Security 采用单向密码编码的设计参见 [密码存储文档](https://docs.spring.io/spring-security/reference/features/authentication/password-storage.html)。

## T20：安全回归与修复

复核 Spring Security 路由边界：`/admin/**` 仅管理员可访问，`/staff/**` 仅管理员和馆员可访问，`/reader/**` 仅读者可访问；本人资料和改密入口要求登录。所有 19 个写入映射均为 POST，没有 GET 写操作。控制器按明确的请求参数读取字段，没有把实体或表单对象批量绑定到账号/业务实体；本人资料更新还会拒绝角色、状态、读者证号、目标用户编号、重复字段等额外参数。

## X03：到书保留、取书与重分配

用户在 X02 完成后授权继续 X03。本步新增 `HELD` 副本状态和 V11 迁移：预约新增保留副本、72 小时截止与取书完成时刻；`PENDING`/`READY` 共用活动读者唯一约束，READY 的副本关联由 MySQL 唯一索引保证一册不能同时保留给两条预约。迁移扩充预约状态检查，并允许副本状态为 `HELD`。

归还或登记新副本时，服务在书目锁内按创建时刻和预约编号 FIFO 分配。为避免与停用事务反向加锁，分配只读候选账号是否启用，不锁其他读者账号或档案；写入按书目、副本、借阅（归还场景）、预约顺序完成。账号停用先锁账号与读者档案，再依书目编号升序取消该读者所有活动预约，释放其保留副本并继续分配。读者也可取消 PENDING 或 READY；取消 READY 与分配在同一事务中释放并继续队列。

测试 profile 的读者页面显示本人排队/保留状态和截止时间；工作人员页面显示 READY 预约，提交时核对读者证号。取书时重新锁定读者和副本并核对账号启用、逾期、借阅额度和同书目借阅限制；资格不足则回滚，不影响 READY 和 HELD 保留。通过后在同一事务新增借阅、将预约改为 FULFILLED、副本改为 ON_LOAN 并写审计。活动预约阻止续借、归档和注销最后一册可流通副本。`library.reservations.enabled` 仍默认关闭，服务和页面继续只在 test profile 存在；dev/prod 直连预约及取书路由均为 404。X03 记录截止时刻但不执行定时到期或请求时过期判断，这部分留给 X04。

## X04：到期处理与扩展启用验收

用户授权继续 X04。本步新增 V12：预约增加 `expired_at`，状态约束包含 `EXPIRED`，状态转换为 `READY → EXPIRED`；已过期预约保留原副本和 72 小时截止历史，不再占用活动读者或活动副本唯一位。数据库约束要求过期时间不早于保留截止、取书时间严格早于截止。

`ReservationExpiryScheduler` 在预约功能启用的 profile 中每分钟扫描 `READY` 且 `hold_expires_at <= now` 的记录。扫描仅查询候选编号，随后逐条开启事务；按 `book → book_copy → reservation（目标及 FIFO 队列前缀按编号升序）` 加锁，重新确认状态和时间，标记过期、释放 HELD 副本、写 SYSTEM 审计，再在同一事务中按 FIFO 交给下一位有效读者。无用户身份的定时任务将重新分配记为 SYSTEM；由取书请求实时触发时，重新分配审计记录当前工作人员。重复扫描只会跳过已终结的记录，不会重复释放、分配或审计。

工作人员取书请求在资格核对前后都按 MySQL `DATETIME(6)` 精度复核时间。截止前 1 微秒仍可完成取书；到达或超过截止则在该请求事务中结束 READY 保留并继续分配，然后向工作人员显示已过期结果，即使定时扫描尚未运行也不能取走旧保留。读者页面显示 EXPIRED；过期预约不可再次取消或取书。过期后预约不再阻止该书目续借。过期操作始终写入 `RESERVATION_EXPIRED` SYSTEM 审计；后续 `RESERVATION_READY` 按触发上下文记账：定时任务为 SYSTEM，工作人员请求触发的实时处理记为当前工作人员。

功能开关仍由 profile 和 `library.reservations.enabled` 同时约束：基础配置关闭、dev profile 关闭、test profile 为真实数据库验收开启。全量验证通过后将 `application-prod.yml` 配置为开启，prod profile 会加载预约路由和每分钟到期调度。生产配置已准备，但没有生产数据库、没有启动 prod profile，也没有部署或发布；prod 数据库结构尚未实测，部署前仍须在目标专用库运行 Flyway 与 Hibernate 校验。
